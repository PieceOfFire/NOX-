# Архитектура Himera

Himera — отдельная копия NOX с дополнительной командой обработки области из Spintegrate. Нет отдельного режима приложения, замены всего спектра или заранее предложенных диапазонов. Соседние проекты не импортируются при запуске и не изменяются.

## Сценарий

Точка входа `main.py` остаётся лёгкой до показа загрузчика; импортируемые имена
`SpectrumApp`/`HimeraApp` разрешаются лениво для прежних сценариев и тестов.
`startup.py` запускает `startup_splash.py` в отдельном процессе с собственным Tk-loop:
импорт NumPy/Matplotlib/SciPy не останавливает анимацию. Этапы передаются UTF-8 JSON
через stdin, без временных файлов. EOF закрывает заставку, в том числе при потере
родительского процесса. Главный поток создаёт рабочее окно, завершает первую отрисовку
и закрывает заставку; только затем входит в основной mainloop. Ошибка загрузки выводится
в терминал и диалог, отмена крестиком имеет отдельный код выхода загрузчика.

Команда Spintegrate → явное выделение X → рабочее окно с живым предпросмотром и настройками модели → группы компонент → Применить → независимые модельные интегралы → прежние формулы. По умолчанию пунктирные кривые выбираются кликом; протягивание области — отдельный инструмент.

Спектр хранится в прежних полях NOX. Результаты лежат отдельно в record.spin_analyses, по UUID подгонки. Конкретный интеграл содержит spin_fit_id; обычный интеграл не содержит этого поля. В одном спектре могут быть оба вида интегралов с одинаковыми границами. Диспетчеризация производится по конкретной записи интеграла, не по координатам или режиму спектра.

Одна область подгонки может содержать несколько интегралов. Новый интеграл содержит spin_fit_id + spin_group_id; состояние модели хранит groups с UUID, именем и индексами компонент. Принадлежность внутри одной модели непересекающаяся, компоненты группы могут быть несоседними. Площадь вычисляется по явному составу, а не по границам области. При повторной подгонке выполняется ограниченное взаимно-однозначное сопоставление центров; исчезнувшие линии отмечаются missing, новые остаются неназначенными. Неполная группа недействительна до ручной проверки. Старые подынтегралы по интервалам по-прежнему выбирают линии по центрам. Формулы используют полную аналитическую площадь выбранной формы, исторический вывод Spintegrate — площадь / π. Изменение вывода не меняет формулы.

Численное ядро поддерживает Lorentzian/Gaussian/pseudo-Voigt с общей HWHM; индивидуальные доли Лоренца хранятся в массиве mixing. Амплитуды, логарифмы ширин, ограниченные сдвиги центров и доли смеси оптимизируются с аналитическим якобианом. Уточнение центров ограничено Гц и серединами между исходными соседями, поэтому линии не меняются местами. Исходные настройки ядра остаются фиксированными лоренцианами для старых рецептов; новые настройки Himera включают уточнение и псевдо-Voigt. `model_component`/`model_component_areas` обеспечивают одну форму кривых и площадей в графиках, группах, формулах и отчётах. Отсутствие mixing в старом проекте означает чистый Лоренц. R² считается по сигналу после локальной линии без отсечения отрицательных значений; постоянный сигнал даёт неопределённый R², не 100%.

Расширенные модели вынесены в `spintegrate/profiles.py` (общие кривые, площади
и FWHM) и `spintegrate/flexible_fit.py` (ограниченная смешанная подгонка).
Поддерживаются настоящий Voigt, асимметричный псевдо-Voigt и Voigt с общей
ограниченной дисперсионной примесью. Старый аналитический solver остаётся для
однородных прежних форм. Гибкий solver использует численный якобиан;
число параметров проверяется относительно числа наблюдений. Дополнительные
компоненты и фоновый член не создаются. Voigt параметризован через полную
HWHM и баланс ширин; нормировка на истинную HWHM задаётся кешированной
таблицей, вычисленной через Faddeeva/поиск половины максимума. Асимметрия
ограничивается отношением сторон, дисперсия — углом до 30°, по умолчанию 15°.

Модель дополнительно сохраняет `line_shapes`, `extra_widths` и
`profile_phases` (радианы). Для Voigt `widths` — gamma, `extra_widths` — sigma;
для асимметричного псевдо-Voigt — левая и правая HWHM. Фаза не меняет массивы
NOX; полная площадь фазовой формы — симметричный предел интеграла, нечётная
дисперсионная часть не добавляется к количественной площади. Централизованный
`model_component_fwhms` не выдаёт gamma за полную ширину Voigt.

Опциональное поле группы `line_shape` переопределяет общую форму. На каждую
ревизию `recipe_for_groups` строит индивидуальные ppm-якоря
`fit.component_shapes` с ограниченным взаимно-однозначным сопоставлением.
Индексы между спектрами не передаются. Форма автоматической группы задаёт
фоновой default solver, но ручные группы, наследующие общую UI-настройку,
получают явные якоря; исходный UI-default сохраняется в `group_default_shape`.
Удаление/изменение состава группы с переопределением запускает пересчёт.
Формы и настройки входят в очередную ревизию, историю и проект; отмена окна
ничего не записывает. Шаблоны и анализ устойчивости перемещают shape-якоря
при постоянном сдвиге ppm. Старые рецепты и модели без новых полей не меняются.

Начальная группа «Вся область» содержит `automatic=True`: `remap_groups` обновляет её по всем текущим компонентам, исключая зарезервированные ручными группами. У неё нет накопленных `missing`. Флаг сохраняется в модели и снимается при явном изменении состава/имени; ручные группы продолжают ограниченное сопоставление с защитой от потерь. Рабочий график не дублирует её сумму поверх общей подгонки. Состав групп и оформление не участвуют в вычислении fitted/R².

`spintegrate/peak_detection.py` — единый детектор для оценки стартовых ширин и
реальной подгонки. Новый default `fit.peak_detection=prominence` проверяет
выраженность и высоту относительно приблизительного линейного тренда,
сглаживает только для поиска, затем возвращает исходные экстремумы и соблюдает
минимальное разделение. Автоматическая выраженность учитывает первый/второй
разностный шум и короткий high-pass остаток для коррелированной ряби.
`fit.min_prominence=0` означает адаптивную оценку; `height` сохраняет прежний
downward-поиск как явную расширенную опцию. После автонастройки количество
кандидатов вычисляется на окончательном локальном фоне тем же `pick_peaks`,
который вызывает solver. Для SNIP используется постоянное продолжение краёв,
а не экстраполяция склонов пиков в искусственный отрицательный пьедестал.

Модель сохраняет опциональный `picked_centers` — детектированные центры до
уточнения формы. `candidate_centers` реконструирует их и в старых проектах из
`center_shifts_hz / sf_mhz`, при несогласованной метаинформации возвращаясь к
консервативному сопоставлению fitted-центров. Переопределения формы и состав
сопоставляются по этим якорям. `component_matches` ограничивает допуск
ближайшими соседями **каждого** старого якоря, не минимальным расстоянием во
всей области. Шаблоны сохраняют и перемещают исходные якоря отдельно от
fitted-центров; без нового поля используются прежние значения. Настоящие
исчезновения и уже накопленные `missing` не скрываются автоматически.

Локальная линия нужна только для подгонки. На основном графике полная модель показывается вместе с этой линией поверх исходного сигнала; кривые отдельных групп не содержат фон, он выводится отдельно. При сохранении подгонки `fit_visible_plot_y` подстраивает Y по видимым точкам спектра и модельных кривых, не по пикам вне текущего X и не по вертикальным маркерам. Обычная перерисовка и отдельные шкалы стека сохраняют прежний Y. Рабочие массивы NOX и численные интегралы не изменяются.

## Модули

- ui_theme.py — единое светлое оформление по образцу обработки спектра: палитра, системные шрифты, кнопки и таблицы. Устанавливается до создания виджетов; диалоги, расчёты и редактор формул используют общие настройки. Цвета узлов и кривых остаются обозначениями данных.
- nox_app.py — исходный главный интерфейс NOX; hooks для встроенных данных проектов и передачи конкретного integral в вычислитель площади.
- himera_app.py — сценарий выделения, фоновые задания, смешанные интегралы, история и проекты.
- spin_dialog.py — переиспользуемая панель параметров и начальный диалог без FID-режима.
- spin_workspace.py — живой редактор подгонки и групп; debounce 350 мс, один worker, latest-wins через номер ревизии, проверка неизменности входных данных при применении.
- spin_groups.py — валидация/площади групп и ограниченное сопоставление компонент между подгонками.
- spin_backend.py — чистый адаптер run_selected_region; используются baseline_correct, pick_peaks и fit_region исходного движка. Raw helpers старой беты не вызываются этой командой.
- spintegrate/core.py — исходный численный модуль коллеги с расширениями Himera; прежний аналитический путь сохранён.
- spintegrate/profiles.py / flexible_fit.py — общие расширенные формы, площади/FWHM и смешанный solver.
- Модули формул, Clean, пресетов, выравнивания и диалогов фазы/линии — из NOX.

Поток получает копии записей, не трогает Tk и рабочие данные; результаты передаются очередью. Изменение параметров не создаёт параллельных solver-потоков; устаревший результат отбрасывается. Только «Применить» записывает модель и все группы одним отменяемым действием. При повторном редактировании ID/номера сохранившихся групп не меняются. При отмене ничего не добавляется. Ошибка отдельного спектра в сравнении блокирует применение всего предпросмотра. Состав групп индивидуален для каждого спектра; UUID/имена общие.

Фаза/линия после подгонки делают её устаревшей: модельные интегралы и формулы показывают недействительный результат. Численные интегралы остаются рабочими. Постоянный X-сдвиг учитывается отдельно.

## Сохранение

`baseline_policy.py` связывает локальную коррекцию с уже применённой коррекцией NOX.
Новые подгонки используют `baseline_policy=nox`, ручной выбор переключает в `manual`.
`baseline_fallback_method` сохраняет запрошенный локальный метод для необработанных
спектров. Политика разрешается на копии рецепта отдельно для каждой записи при запуске
и автонастройке, с учётом границ `baseline_steps` и сдвига сравнения. Для старой коррекции
без метаданных диапазона выбирается none, чтобы автоматически не вычитать фон повторно.
Ранее сохранённый рецепт без политики считается ручным. Смена спектра обновляет пояснение
и отображаемый метод, не создавая лишнего пересчёта.

`baseline_methods.py` — общий каталог расширенной коррекции NOX и адаптер к ядру Spintegrate.
CorrectionDialog расширяет короткое меню до полного списка и повторно раскрывает
его через idle-callback. `baseline_options.BaselineParameters` отображает только нужные
поля выбранного метода внутри этого же окна и запускает отложенный предпросмотр.
Адаптер упорядочивает X и учитывает полярность. В `baseline_steps` расширенный метод хранится
как `Spintegrate: <id>` с численными `parameters`, которые проверяются и воспроизводятся
`processing_templates.py`. Стандартный адаптивный NOX и параметрический arPLS Spintegrate
остаются отдельными вариантами в списке.

`spin_history.py` хранит ограниченную локальную историю рабочего окна (20 состояний).
Неизменяемые модели и массивы используются совместно, а составы групп, настройки и имена
копируются. Успешный пересчёт или изменение групп создаёт точку истории. Отмена незавершённой
ревизии восстанавливает последнюю принятую; устаревший worker не может её заменить.
Новый solver не запускается параллельно предыдущему; оставшиеся спектры устаревшей серии
пропускаются. Восстановление настроек через `set_recipe(notify=False)` не запускает solver.

Выбор хранится по исходным центрам и сопоставляется тем же ограниченным алгоритмом,
что и группы. Масштаб X/Y и остатка хранится отдельно для каждого спектра.
`spin_controls.ParameterPage` обеспечивает локальную прокрутку панелей без `bind_all`;
колесо числовых полей сохраняет тонкую настройку. Состояние проекта меняется только при Apply.

Проект сохраняет массивы NOX, параметры инструмента, все модели и привязки интегралов к ним. При загрузке оптимизация не повторяется. Сохраняются сравнения и рабочая схема формул. Старые проекты NOX читаются как прежде; первая бета Himera преобразуется в явные привязки прежних модельных интегралов.

## Количественный рабочий процесс

`WorkflowMixin` добавляет команды диагностики, шаблонов серии, устойчивости и отчёта. `ResultsWindow` передаёт фоновые результаты очередью, закрытие окна отменяет применение. Шаблон выполняется на копиях записей; только успешный предпросмотр всей серии можно применить. Снимок `workflow_records` содержит записи, сравнения, счётчик сравнений и документ формулы: отмена/повтор возвращает всю операцию вместе.

Шаги базовой линии (`baseline_steps`) записываются при подтверждении диалога, входят в историю и проект. Новая фаза очищает их вместе с коррекцией. Старая коррекция без рецепта помечается как невоспроизводимая для шаблона. `processing_templates.py` воспроизводит фазу и вычитания из исходного сигнала, выравнивает шкалу и пересчитывает локальные модели. Центры групп сопоставляются взаимно-однозначно; отсутствующая линия не превращается в соседнюю или нулевой результат.

`signal_quality.py` оценивает шум по разностям, фон по боковым полосам и чувствительность границ. `sensitivity.py` создаёт независимые варианты и оценивает тот же граф формулы через `FormulaEngine`; модельные группы сопоставляются после каждой подгонки. Диапазон отражает только выбранные варианты, не статистическую неопределённость. `report_export.py` сохраняет данные и SVG в один HTML без внешних ресурсов. Устаревшая оценка устойчивости в отчёт не включается.
